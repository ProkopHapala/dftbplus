# Sparse Chebyshev+Ritz Eigensolver — Scaling Benchmarks on Carbon Ribbons

**Date:** 2025-09-06
**Code path:** Sparse eigensolver (Cholesky-transformed implicit operator + Chebyshev filter + Rayleigh-Ritz)
**Reference:** Dense LAPACK `dsyevd` generalized diagonalization (`nalgebra::SymmetricEigen`)
**Hardware:** CPU (Python + SciPy/BLAS) — no GPU involved in this path

## Scope — what this report covers

This report benchmarks the **sparse iterative eigensolver** used for large
PAHs, graphene flakes, and carbon nanoribbons — systems where the Hamiltonian
`H` and overlap `S` are sparse and a few frontier orbitals (HOMO/LUMO) are
needed without full O(N³) diagonalization.

This is a **different code path** from the GPU SCC dense multi-system solver
(`doc/prokop/reports/2025-09-06_gpu_scc_benchmarks.md`), which uses direct
Jacobi diagonalization on GPU for small batched systems (formic dimers,
H-bond exchange). The two paths serve different system-size regimes:

| Path | Method | Use case | Report |
|------|--------|----------|--------|
| Dense multi-system GPU | Batched Jacobi eigensolver, DIIS SCC | Small systems (N<100), many replicas | `2025-09-06_gpu_scc_benchmarks.md` |
| Sparse Chebyshev+Ritz | Cholesky-transformed implicit operator, polynomial filter | Large PAHs, ribbons, flakes (N=76..1156+) | **this report** |

## Methodology

### Benchmark script

`scripts/ribbon_scaling_test.py` — runs the sparse solver on all ribbon TSV
files and produces timing/nnz/parity CSV+JSON+plots.

### Solver pipeline

1. **H/S construction** (Rust, non-SCC): `dftb_engine --script test_ribbons_sparse.rhai`
   builds `H0` and `S` via `HamiltonianBuilder::build_non_scc` (general path,
   handles mixed C/H species). Exports to `*_hs_matrix.tsv`.
   - Non-SCC `H0` is used (no charge self-consistency) to isolate the
     eigensolver benchmark from SCC convergence behavior.
   - SCC reference validation is done separately on small PAHs (see
     `2025-09-05_3way_homo_lumo_wavefunctions.md`).

2. **Sparse Cholesky** (Python/SciPy): `S = L Lᵀ` via
   `scipy.sparse.linalg.splu` with `SymmetricMode`, then `L_chol = L·sqrt(D)`
   from the LDLᵀ factorization.

3. **Implicit operator** (Python): `H'·v = L⁻¹·(H·(L⁻ᵀ·v))` — two triangular
   solves + one SpMV per matvec. `H'` is never formed explicitly.
   - Dense BLAS triangular solves (`scipy.linalg.solve_triangular`, `dtrsm`)
     for N < 2000 (12× faster than sparse `spsolve_triangular`).
   - Sparse triangular solves for N ≥ 2000.

4. **Spectral range rescaling**: power iteration estimates `[λ_min, λ_max]`
   of `H'`, maps to [-1, 1] via `(H' - center) / half_range`. Rayleigh-Ritz
   runs on the original operator to recover true eigenvalues.

5. **Chebyshev band-pass filter + Rayleigh-Ritz**: two bands (HOMO, LUMO),
   `nvec` random probe vectors, `cheb_deg`-degree polynomial filter applied
   `iters` times with QR orthonormalization between applications.

### Adaptive parameters

| N_orb | nvec | cheb_deg | iters | SpMV/band |
|-------|------|----------|-------|-----------|
| < 300 | 20 | 40 | 20 | 128,040 |
| < 800 | 30 | 60 | 30 | 432,060 |
| ≥ 800 | 40 | 80 | 40 | 1,024,080 |

### Dense reference

For each ribbon, the dense reference is computed via
`nalgebra::SymmetricEigen` on `S^{-1/2} H S^{-1/2}` (O(N³) generalized
diagonalization). This is the timing labeled `t_dense` in the tables.

For the largest systems (N>580), dense diagonalization becomes the
bottleneck (285s for N=1156), which is the motivation for the sparse solver.

| N_orb | nnz(S) | nnz(L) | Fill ratio (L) | nnz(L)/nnz(S) |
|-------|--------|--------|----------------|---------------|
| 76 | 2,588 | 1,829 | 31.7% | 0.71 |

| 580 | 25,436 | 89,441 | 26.6% | 3.52 |
| 1,156 | 51,548 | 348,929 | 26.1% | 6.77 |

The fill ratio of L **decreases** with N (32% → 26%), confirming sub-O(N²)
fill-in for these 1D-localized ribbons. However, `nnz(L)/nnz(S)` grows
(~0.7 to ~6.8), meaning Cholesky fill-in is superlinear in `nnz(S)` —
the factor is ~7× denser than S at N=1156.

## Key findings

### 1. Sparse beats dense for N ≥ 148

The crossover is at ~148 orbitals (52 atoms). Below that, the dense O(N³)
diagonalization is fast enough that the sparse solver's overhead (Cholesky +
spectral estimation + many matvecs) dominates. Above 148, the sparse solver
is 1.7× to 7.5× faster.

### 2. All parities at machine precision

Across all 5 ribbon sizes (N=76 to 1156), HOMO/LUMO eigenvalues match the
dense reference to 1e-11 to 1e-12 Ha. Max residuals range from 1.4e-16 to
7.5e-11. No accuracy degradation with system size.

### 3. Chebyshev+Ritz dominates, not Cholesky

Cholesky factorization is fast (306ms for N=1156 — 0.9% of total). The
Chebyshev filter + Rayleigh-Ritz iterations dominate (99% of total time).
The cost scales as `nvec × cheb_deg × iters × 2` matvecs per band.

### 4. Spectral rescaling is critical for correctness

Without rescaling `H'` to [-1, 1], the Chebyshev filter passes the wrong
part of the spectrum for N > 580. L=64 produced eigenvalues at +1.2 instead
of -0.18 before this fix. The power-iteration spectral estimate adds ~1s
but is essential.

### 5. Dense BLAS triangular solves are 12× faster than sparse

At N=216, dense `dtrsm` (0.07ms) vs sparse `spsolve_triangular` (0.85ms).
The crossover is ~N=2000 where the dense L matrix becomes too large. For
the current benchmark (max N=1156), dense solves are always used.

## Optimizations applied (chronological)

1. **Dense BLAS triangular solves** (12× per-solve speedup): Replaced
   `scipy.sparse.linalg.spsolve_triangular` with
   `scipy.linalg.solve_triangular` (BLAS `dtrsm`) for N < 2000.
   Controlled by `DENSE_SOLVE_THRESHOLD` in `sparse_homo_lumo.py`.

2. **Spectral range rescaling** (correctness fix): Added
   `estimate_spectral_range()` (power iteration) and `RescaledOp` wrapper.
   Without this, large N produces completely wrong eigenvalues.

3. **Adaptive Chebyshev parameters**: nvec/deg/iters auto-scale with system
   size (see table above). Previously fixed at nvec=12, deg=40, iters=20,
   which was insufficient for N > 580.

4. **More probe vectors** (nvec 12 → 20 → 40): Increasing probe vectors
   improved circumcoronene HOMO error from 1e-5 to 2.5e-8. Larger systems
   need more vectors to capture the denser spectrum near the gap.

## Remaining bottlenecks

1. **Python callback overhead**: `RescaledOp.matvec` adds a Python layer
   (subtraction + division) on top of BLAS triangular solves. Moving the
   full operator to Rust/OpenCL would eliminate this.

2. **Chebyshev iteration count**: For N > 800, 40 iterations × 80 degree =
   3200 matvecs per band. A Lanczos/LOBPCG eigensolver might converge with
   fewer operator applications.

3. **Dense triangular solves for N > 2000**: the dense L matrix becomes too
   large and we must switch to sparse triangular solves (12× slower per
   solve). A GPU triangular solve kernel would bridge this gap.

4. **Cholesky fill-in for 3D**: for 3D systems, fill-in will grow faster
   than O(N). Hierarchical factorization (HSS/STRUMPACK) would be needed.

5. **No GPU implementation**: the Chebyshev filter + triangular solves run
   on CPU. A GPU port would need triangular solve kernels (not standard in
   OpenCL) or an iterative sparse solve alternative.

6. **Not wired into SCC loop**: currently a post-SCC or non-SCC eigensolver.
   Wiring into the SCC loop would require re-running the filter each
   iteration (H changes) or a CheFSI-style update.

```bash

cd rust_dftb
cargo run --bin dftb_engine -- --script scripts/test_ribbons_sparse.rhai

# 2. Run sparse solver scaling benchmark
cd ..
python3 scripts/ribbon_scaling_test.py

# 3. Or run sparse solver on a single ribbon
python3 scripts/sparse_homo_lumo.py debug/graphene_sparse/ribbons/zigzag_w4_L64_hs_matrix.tsv
```
