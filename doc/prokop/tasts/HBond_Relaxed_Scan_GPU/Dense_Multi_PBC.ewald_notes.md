# PBC electrostatics in Fortran DFTB+ — reference notes for the GPU port

Source survey of `src/dftbp/` (this repo's Fortran reference). Purpose:
exact spec for the complex/PBC `GpuPbcPlan` charge-potential path and the
parity tests that will validate it.

## THE key architectural fact: DFTB+ does NOT Ewald the γ function

`γ_AB` is split into a long-range part (pure Coulomb, Ewald-summed) plus a
short-range *difference* correction evaluated over a real-space neighbor
list (`scc.F90:563`, `shortgamma.F90:286,341`):

```
gammamat(:,:)  =  invRMat                          ! Ewald 1/R, all pairs
gammamat(iB,iA) -= shortGamma_(iNeigh, iA)         ! per real-space image in short cutoff
```

where `shortGamma_ = expGamma(r, U_B, U_A)` and `expGamma` is **not** γ —
it is `1/r − γ_func(r)` for r>0 (see sign note below), so the net result is

```
γ_pbc[A,B] = Ewald(1/R)[A,B] + Σ_{R ∈ short-cutoff} [ γ_func(|r_AB + R|) − 1/|r_AB + R| ]
```

`γ_func − 1/r` decays like e^{−τr} → the short-range sum converges within
a few Å; all long-range 1/r physics lives in `invRMat`. This is why the
short-range neighbor list is the *ordinary* SK-type list (cutoff from
`expGammaCutoff`, `minShortGamma=1e-10`), while the real-space Ewald sum
needs its own much longer list.

For the GPU port this means the γ buffer splits into:
- `invRMat[n_at²]` — built once per geometry (real + reciprocal + self + const, below);
- `γ_pbc = invRMat − Σ_short expGamma` — same kernel structure as the existing
  molecular `build_gamma`, but evaluated over image-augmented pairs;
- `V = γ·Δq` — the existing `zdq_v_batched` kernel needs NO change.

## The Ewald 1/R matrix (`invRPeriodicSerial`, coulomb.F90:963)

For each atom pair (A,B) — symmetric, lower triangle only:

```
invRMat[A,B] = Σ_{R ∈ neigh(A, maxREwald)}  erfc(α·|r_AB + R|) / |r_AB + R|     (real part)
             + (4π/V) · Σ_{G>0, |G|<maxGEwald}  e^{−G²/4α²}/G² · cos(G·r_AB)    (reciprocal)
             − π/(V·α²)                                                          (G=0/background)
             − (2α/√π)·δ_AB                                                       (self, r=0 cancel)
```

Details that matter:

- **Real part** iterates the *dynamic* neighbor list (`TDynNeighList`,
  cutoff `maxREwald`): per atom A, every image of B within cutoff,
  `img2CentCell` maps image→central B. Each (A,B) ordered once — the
  pair's images are all enumerated from the A side. Self-image at r=0 is
  excluded (convention: `ewaldReal` skips `|r+R|² < tolSameDist²`,
  `tolSameDist = 1e-5`); the −2α/√π self term replaces it on the
  diagonal.
- **Reciprocal part** sums over `gLatPoints_` = G-vectors in CARTESIAN
  units (already multiplied by `recVecs`, which **include 2π** — DFTB+
  convention `recVecs = 2π·B`, B = latVecs^{−T}). The list is generated by
  `getLatticePoints(recVecs, latVecs/2π, maxGEwald, onlyInside=.true.,
  reduceByInversion=.true., withoutOrigin=.true.)`: half of reciprocal
  space only, hence the **factor 2** in `recSum = 2·Σ·4π/V`.
- `−π/(Vα²)` is added to **every** element including off-diagonal — it is
  the G=0 neutralizing-background term. This is what makes **charged
  cells** work (net ΣΔq ≠ 0 gets finite energy via the background).
- The reciprocal term is applied to **all** pairs including A=B
  (the diagonal gets reciprocal + const + self-term, no real part at R=0
  beyond the self cancellation).
- `invRMat` is stored **lower-triangle only**; `updateShifts` uses
  `hemv(...,'L')` (coulomb.F90:576).

## Parameter autotuning (coulomb.F90:1763–1976, all bisection, nSearchIter=30)

- `alpha`: input `EwaldParameter` (0 → auto). Auto = bisection root of
  `diffRecReal(α) = [gTerm(4·minG) − gTerm(5·minG)] − [rTerm(2·minR) − rTerm(3·minR)] = 0`
  within `tolEwald`, bracketed by doubling from 1e-8. `minG`,`minR` =
  shortest reciprocal/real lattice vector lengths. The heuristic balances
  real vs reciprocal truncation error at ~4–5× the shortest periods.
- `maxREwald`: bisection for `rTerm(r,α) = erfc(αr)/r = tolEwald`.
- `maxGEwald`: bisection for `gTerm(g,α,V) = 4π·e^{−g²/4α²}/(V·g²) = tolEwald`.
- `tolEwald` = input `EwaldTolerance`, default **1e-9** (parser.F90:3260).
- `erfwrap`/`erfcwrap` = plain `erf`/`erfc` (f64; on GPU we need an f64
  or accurate-f32 erfc — math is scalar-per-term, f64 fine per §3).

## `expGamma` = 1/r − γ_func (shortgammafuncs.F90:97)

τ = 3.2·U (=16/5·U). For r ≥ tolSameDist:

- same U (|Ua−Ub| < minHubDiff, minHubDiff = 0.3125e-5):
  `expGamma = e^{−τr}·(1/r + 11τ/16 + 3τ²r/16 + τ³r²/48)`
- different U: `gammaSubExprn_(r,τA,τB) + gammaSubExprn_(r,τB,τA)`
- r→0 (on-site, NOTE SIGN CHANGE): `expGamma = −Ū` same-U,
  `= −½(τAτB/(τA+τB) + (τAτB)²/(τA+τB)³)` different-U — i.e. it encodes
  `γ_func(0) − 1/r → −U` with the singular 1/r dropped.

Sanity: cluster case has invRMat = 1/r (diag 0), γ = invR − expGamma →
off-diag γ_func within cutoff and 1/r outside (exact merge), diag
`0 − (−U) = U`. ✓ In the periodic case the same subtraction gives
γ_AA = U + (Ewald self + reciprocal + const) — Hubbard U plus the atom's
Madelung-type self-potential from its own images.

- `expGammaCutoff(U2,U1,minValue)`: doubling + bisection for where
  expGamma < `minShortGamma` (1e-10) — that drives `shortCutoffs_` and the
  neighbor count `nNeigh_` per (U-pair, species-pair, atom).
- `shortGamma_(iU2,iU1,iNeigh,iAt1)` is precomputed per (atom, neighbor)
  at `updateCoords` — on GPU this is one elementwise kernel over the
  image-augmented pair list.

## How it enters SCC (`scc.F90`)

- `updateCoords` → `invRPeriodic` **once per geometry** (not per iteration).
- `updateShifts` **every SCC iteration**: `shiftPerAtom = hemv(invRMat, Δq)`
  (coulomb.F90:576) plus shell-resolved short-γ shifts
  `shiftShell −= shortGamma·ΔqShell` (`buildShifts_`, shortgamma.F90:918 —
  note the MINUS, same convention as the matrix subtraction).
- Energy: `E_scc += ½·Σ_A shiftPerAtom_A·Δq_A` (coulomb.F90:398). With
  Δq = "negative gross charge" = electrons − neutral.
- Hamiltonian: `ham = H0 + ½·S·(shift_A + shift_B)` applied in *sparse
  real space* by `addShift` (hamiltonian.F90:386) then folded to k —
  for us `zhscc_batched` already does this in k-space.

## Bloch folding conventions (for the H(k)/S(k) stage)

`unpackHS_cmplx_kpts` (sparse2dense.F90:240):

```
H(k)[j2f-block, j1-block] += exp(i·2π·k_frac·cellVec) · H_sparse[(A1, image A2)]
```

- `kPoint2p = 2π·kPoint`, kPoint **fractional** (units of reciprocal
  vectors); `cellVec(:, iCellVec(iAtom2))` = integer cell shift of the
  image; `iCellVec`/`img2CentCell` come from the SK neighbor list.
- Sparse blocks stored per (A1, neighbor-image of A1); only blocks with
  `j2 ≥ j1` are written (lower part; Hermitian completion implied).
- Density back-fold (densitymatrix.F90:514):
  `D(R) += w_k·Re[ρ(k)·e^{−i·2πk·R}]` — conjugate phase.
- H(−k) = H(k)* follows automatically.

## Neighbor lists — there are THREE

1. **SK list** (`TNeighbourList`, periodic.F90): static, cutoff = max SK
   cutoff. Enumerates all image atoms within range; `img2CentCell`,
   `iCellVec` (integer cell index into `rCellVec`/`cellVec` tables from
   `getCellTranslations` with ±1 extensions). Used for H0/S assembly,
   short-γ, forces. Pairs stored only for i≤j of the central cell.
2. **Ewald real-space list** (`TDynNeighList`, dynneighlist.F90):
   dynamic per-atom iterator (`TNeighIterator`, chunk 1000), cutoff =
   maxREwald — usually ≫ SK cutoff. Used only by `invRPeriodic`/forces.
3. **`rLatPoints_`** (`getCellTranslations`, all R within maxREwald
   incl. origin): only for the *asymmetric* sums — external charges
   (`sumInvRPeriodicAsymm`) and potential evaluation, where each
   (atom, charge) pair sums the full lattice.

For the GPU plan we can replace (2) by a precomputed per-pair R-list or a
dense Σ_R over `rLatPoints_` — assembly-phase cost, once per geometry.

## Forces / stress (for later, not needed for stage-1 charges)

- Real deriv: `derivRTerm = r̂·(−2/√π·e^{−(αr)²}·αr − erfc(αr))/r²`·(r vector) —
  `= r·(−2α/√π·e^{−α²r²}·... )` exactly `r·[−(2/√π)αr·e^{−α²r²} − erfc(αr)]/r³`.
- Reciprocal deriv: `derivEwaldReciprocal = −(8π/V)Σ_G G·sin(G·r)·e^{−G²/4α²}/G²`.
- Stress: `derivStressEwaldRec` adds σ = (8π/V)Σ_G [−I + 2(1/4α² + 1/G²)GG^T]cos(G·r)e^{−G²/4α²}/G²;
  reference Aguardo & Madden, JCP 119, 7471 (2003).
- Short-γ force adds `−expGammaPrime·Δq_A·Δq_B·r̂` pair terms (shortgamma.F90:396).

## External / blurred charges

`sumInvRPeriodicAsymm` + `ewald()`: same Ewald but per (probe, source)
pair over the full rLatPoints + gLatPoints lists; optional `blurWidth`
replaces the real term by `erf(r/σ)/r − erf(αr)/r` (Gaussian-smeared
source minus compensating Gaussian); `epsSoften` → 1/√(r²+ε²). Needed
later for explicit charge environments / QM-MM.

## What this means for `GpuPbcPlan` — concretely

Buffers/kernels to add (all assembly-phase, once per geometry, zero cost
in the SCC loop):

1. `rLatPoints`/`gLatPoints` host generation (port `getLatticePoints` —
   small integer grid enumeration, do it on CPU, upload once) +
   `alpha`, `maxREwald`, `maxGEwald` via the same bisections (port
   `getOptimalAlphaEwald`/`getMaxREwald`/`getMaxGEwald` verbatim — cheap
   scalar host code).
2. `kernel invr_ewald_batched`: per (rep, A≤B): real part over the
   per-pair R-list + reciprocal over gLatPoints + self + const →
   `invRMat` [n_rep·n_at²] f32 buffer (f64 accumulation inside the
   kernel, one output write — gather-in/own-out).
3. `kernel gamma_short_batched`: `γ_pbc = invRMat − Σ_short expGamma`
   over the image-augmented atom-pair list (needs per-pair U_A,U_B —
   the existing `buf_u_hub` per-atom U already exists).
4. `zdq_v_batched` unchanged: V = γ_pbc·Δq (it already does a dense
   n_at² matvec).
5. Boundary conds: only `pbc3d` + `cluster` are implemented upstream;
   helical exists in periodic.F90 but not in coulomb.F90 — same scope
   for us.

## Parity-test targets (vs Fortran, bit-exactness not expected — f32 vs f64)

1. `invRMat` element parity on a small cell (dump Fortran invRMat via a
   debug print or a tiny driver; compare max|Δ|).
2. `γ_pbc` element parity on same cell.
3. Γ-point (or few-k) **eigenvalues** of H_scc(k) vs Fortran `detailed.xml`/
   `band.out` for a neutral cell — end-to-end.
4. Charged-cell regression: net-charge case works because the −π/(Vα²)
   background term is in invRMat — test a charged cell vs Fortran.
5. Convergence-in-tolerance test: E_scc(α, tolEwald=1e-9) stable vs
   doubling maxREwald/maxGEwald manually.
